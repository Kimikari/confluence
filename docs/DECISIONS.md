# Decisions and ambiguity log

Precedence: (1) the explicit build requirements in `docs/confluence/confluence-claude-code-prompt.md`, (2) the design's global rules (`confluence-design.md` §1–16 and the rule chapters), (3) individual catalogue definitions (`confluence-catalogue.json`). JSON is canonical for record data; the Markdown mirrors it and is canonical for rule prose. Spec line references use `node tools/spec.mjs`.

## Engine and toolchain

**D-001 Engine: Unity 6000.6.4f1.** Installed toolchain (2026-10-01): Unity 6000.4.5f1 (no build targets installed) and 6000.6.4f1 (Windows Mono and IL2CPP player plus Windows Dedicated Server modules), .NET SDK 10.0.401, Node 24, Visual Studio, Git. No Python, Godot, or Unreal. Unity 6 is the user's existing engine convention (Arcane Duel). 6000.6.4f1 is the only install that can build Windows players. Its manual confirms Roslyn with C# 9.0, .NET Standard 2.1 as the default API level, and support for netstandard2.1 managed plug-ins. The license is activated through Unity Hub.

**D-002 Engine-agnostic authoritative core.** Rules are C# `netstandard2.1` libraries (C# 9) with no Unity dependency. The authoritative server is a .NET 10 console app, not a Unity dedicated-server build. Reasons: the server must own every outcome (§14), client prediction must run identical movement code, tests must run quickly through `dotnet test` without an editor, and replays need rule-level determinism. Unity consumes the same compiled DLLs, synced by `tools/sync-unity.ps1`.

**D-003 Custom kinematic collision instead of Unity physics.** Arena gameplay geometry is validated boxes, yaw-rotated boxes, and ramps (§4, §7). The core provides capsule-vs-solid character movement, raycasts, and sphere sweeps, so the server and client prediction share exact behavior. Unity colliders are presentation only.

**D-004 Transport: LiteNetLib (MIT) over UDP.** It provides reliable-ordered and unreliable-sequenced channels from pure C#, so the identical DLL runs in .NET 10 and Unity Mono/IL2CPP.

**D-005 Tick model.** 60 fixed ticks per second (§14). Durations are stored as integer ticks. Snapshots go out at 30 Hz by default and drop to 20 Hz under congestion.

**D-006 JSON parsing in-house.** A small recursive-descent parser in Core avoids divergence between Newtonsoft, System.Text.Json, and Unity JsonUtility. The supplied catalogue is loaded unchanged at runtime.

**D-007 Tests: xUnit on net10.0**, one test project per library. Content verification tests carry `[Verifies("ID")]` so the ledger can be generated.

## Content implementation policy

**D-010 Availability gating.** Draft and shop pools contain only records whose behavior is implemented, so a menu entry is never an empty handler. The full catalogue remains loaded and validated, and the codex/Laboratory can display unimplemented records labeled as such. Match start asserts the design floors (ten legal augments per rarity per wizard and loadout; enough equipment for three offers plus rerolls). If a floor fails, the server reports the gap instead of silently shrinking the rules.

**D-011 Prose parameters.** Numeric fields present in the JSON (mana, cooldown, cast_time, range, tier, durability) are read from the catalogue. Parameters that exist only in prose (speeds, radii, units, durations) are written in the behavior code with the quoted source phrase. A test asserts each declared number appears in the record's text.

**D-012 Structural deltas.** A transformation's change to structural spell tags (for example projectile → trap/field) is declared once in `Core.Content.StructuralDeltas` and used by both Economy eligibility and Sim. Without a declaration, a transformation keeps the base spell's structural tags.

## Rule interpretations

**D-020 Equipment offer draw.** "Drawn from unlocked affordable tiers, then uniformly among legal definitions in a tier" (§5) is interpreted as: choose uniformly among unlocked tiers whose price ≤ current balance and that contain at least one legal, implemented, non-visible definition; then choose uniformly within that tier.

**D-021 Duplicate predicate children.** Some `any` lists repeat identical leaves (for example AUG-142 lists `school:heat` four times). They are evaluated as written; duplicates are harmless and are not "fixed" in the catalogue.

**D-022 Feats are rule data.** FEAT-001…FEAT-024 come from the §5 table, not the JSON. They live in `Core.Rules.Feats` so predicate validation can confirm referenced feat IDs exist.

**D-023 Wind moves clouds only above strength 1.** Spec L151: "A directional force above strength 1 translates the volume at up to 3 meters per second; strength 2 disperses its front 2 meter slice." Catalogue strengths are integers, so translation needs strength 2 or more (`GlobalRules.World.WindTranslatesClouds`). Seventeen records carry a strength-1 wind or force; only SPL-105 ("Wind 1 displaces smoke/steam 2 m"), SPL-110 ("Wind 1 scatters nearby mist within 1 m once"), and BIO-011 ("gust moves clouds up to 2 m ... force strength 1") say they move clouds. Those are binding local prose effects (L300) implemented by their own behaviors with their stated bounds; they do not loosen the global rule. The other strength-1 sources (SPL-089, -090, -093, -096, -113, -115, -117, -225, -226, -227, -229, -230, AUG-497, AUG-506) never move steam or dust.

**D-024 Movement and traversal constants the spec leaves open.** Chosen once in `GlobalRules.Movement` / `GlobalRules.Terrain` so the Sim motor, client prediction, and the arena validator share them:
- Gravity 18 m/s² (the Laboratory may edit it, L69). Common jump apex 1.1 m, so launch speed sqrt(2gh) ≈ 6.29 m/s and level airtime ≈ 0.70 s. The airtime outlasts the 0.6 s wet charge that "jump the short pulse" counters (L148); the apex reaches the one-meter ledges and terraces of MOD-030 and MOD-066 and stays far below the 3 m fall-damage threshold (L175).
- Ground acceleration 50 m/s² (about 0.11 s to walk speed). Air acceleration 8 m/s²: over one jump the horizontal velocity changes by at most about 5.6 m/s, enough to stop a 5.5 m/s run but not to reverse it ("Air steering is moderate and cannot reverse horizontal momentum immediately", L80).
- Crouch speed 2.75 m/s (half of walk). Capsule radius 0.4 m, height 1.8 m standing and 1.2 m crouched, eye height 1.6 m and 1.0 m. Two players fit side by side within the 2.5 m minimum route width (L312).
- Step height 0.35 m; standardized stair risers stay below it (L312 "stairs and collision edges are standardized").
- Traversable routes contain gaps of at most 1.5 m and ledges of at most 1.0 m (L312 "Traversable gaps require only the common jump"; MOD-033 uses a one-meter gap). A walking jump covers about 3.8 m, so the margin absorbs late take-offs and latency.
- Moving props deal their 5/15/25 collision damage (L173 "above their threshold") only at a relative impact speed above 3 m/s, for every mass class.

**D-025 Cells carry sand and growth units.** L136 lists water, heat, frost, and dust units, but L154 compares equal water and sand units, L153 ignites growth with at least two heat units, and the catalogue states quantities (BIO-007 "Two 2 m beds start with Sand 2 Water 1", BIO-002 "Heat 1 and Growth 1", EQP-118 "Growth strength 1"; Sand and Growth 1-3 appear 41 times). Cells and `Arena.MaterialPatch` therefore also store Sand and Growth unit counts, capped at four like every strength (L163). `MaterialFlags.Sand` and `MaterialFlags.Growth` still mark the material type. The generator, Reactions, preview, and replays read the same counts.

**D-026 Contraction easing.** L48 fixes only the start (55 s) and end (85 s). Each boundary radius moves toward the final radius along a smoothstep in time (`BoundaryContour.ContractionProgress`). The edge starts and stops without a jump in speed, so the announced start reads clearly and the final floor settles. Its peak speed is 1.5 times the linear rate: about 1.0 m/s for a 48 m arena (24 m to 4 m over 30 s), far below walk speed.

**D-027 The final floor is 8 m across.** L48 "the validated central 8 meter duel space" and L678 "the anchored eight-meter floor" give a diameter, so the final radius is 4 m (`GlobalRules.Boundary.FinalFloorDiameter`). MOD-066 places "a level eight-meter final floor" inside a 10 × 10 m center module, which a 16 m floor could not fit.

**D-028 Arena diameter sequence.** L306: rounds form consecutive sets of four scheduled rounds (1-4, 5-8, 9-12, then bracket rounds 13 onward). Each set uses every diameter once, in an order drawn uniformly from the match's Arena stream. No 24 m round may be followed directly by a 48 m round, inside a set or across a set boundary. "24 then 48" is read as ordered, so 48 then 24 is allowed. Under this reading a legal order always exists; the "unless needed to preserve the four-round set" clause stays as a fallback that never triggers. A tied-round replay keeps its round's diameter. See `Schedules.ArenaDiameterSequence`.

**D-029 round_at_least uses Conclave round numbers.** The thresholds follow the Conclave draft schedule: AUG-006 round 3 is the second Silver draft, and AUG-021 round 9 is the first Prismatic draft. Duel compresses the same six drafts into rounds 1-6 (L225), so a literal comparison would make both augments impossible to draft in Duel. Evaluators compare against `Schedules.PredicateRound`: Conclave rounds pass through unchanged, and Duel round r maps to 2r − 1, the Conclave round holding the same draft. Feat thresholds count actual completed duels in either mode (`Schedules.CompletedDuelsBefore`), because a feat records events, not a schedule position.

**D-030 Known witness gaps in the supplied catalogue.** L643 requires every alternative branch of a condition to have a concrete acquisition witness. With no structural deltas declared yet, the validator warns about six records. AUG-056 needs an Earth spell that also carries terrain, and no base spell is both. AUG-063, AUG-130, AUG-134, AUG-226, and AUG-239 each have a spell alternative that no single kit can meet together with the rest of the condition: Growth field with terrain, Growth or Venom field with Water, and summon with Frost or terrain. In each of those five, the equipment alternative (EQP-118, EQP-116, or EQP-117) remains a working witness. These are warnings, not errors, because a transformation's structural delta (D-012) may supply the tag later, and the draft sampler only offers eligible records. Re-check them when Stage 5 registers deltas.

**D-031 Compound acquisition predicates are all/any roots.** L596 states 121 compound predicates. The supplied shared augments have exactly 109 `all` plus 12 `any` roots. The three `not` roots (AUG-241, AUG-245, AUG-246) negate a single leaf and are not compound.

**D-032 Acquisition-plan validation.** `CatalogueValidator` checks each augment against the actual draft schedule of both modes (L600, L643). A new definition takes one free choice at a draft of exactly its rarity, and a rank 2 takes a later choice. Compulsory parents come first, recursively, and round and feat thresholds must hold at the drafting round. `any` branches and enumerated-ID count leaves are alternatives; unrestricted count leaves need unnamed parents. A child occupies one of the six slots, so count leaves can require at most five parents. `equipped_tag` counts are bounded by a matching of Unique groups to the eight equipment slots (L210). Satisfiability is checked per wizard: one wizard must own the named spells and transformations and carry the required spell profiles in one kit. Searches that exceed their budget are treated as satisfiable, so the check reports no false errors. A worked build's own loadout is checked against its listed augments in the Economy stage (see IMPLEMENTATION_PLAN), because that needs the production predicate evaluator and structural profiles.

## Stage 1 — Reactions (`src/Confluence.Reactions`, design notes in `docs/notes/reactions.md`)

**D-033 Steam formation.** L144: each formation consumes 1 heat + 1 water, and a cell repeats it while both remain (Heat 2 on Water 2 steams 2 units). One cloud per (committing owner, source event) per step; an unmoved cloud from the same source grows instead of taking a new field slot. "2 meter rise" is a cloud 2 m above the surface.

**D-034 Reaction ownership.** L670: the owner is the slot with the later server event id (the last direct source). Steam made from map-owned heat and water belongs to the map and is nobody's field (`CountsAsField = false`).

**D-035 Ice tiles.** L145–L147: a tile forms only on a cell without ice; leftover frost stays as units. When a 5 s tile expires its frozen water is gone; map ice (BIO-004) never expires by time and melts into natural water. Water from a melted tile keeps the tile's remaining lifetime (L146). Hits under 20 direct damage wear the 45 durability, and a tile worn to 0 breaks without shards. A hit of 20 or more breaks the tile and emits one shard cone (1 m, 10 physical, each body once) with a 45° half angle (the spec gives no angle); a vertical strike sprays all around. Brittle solids emit the same cone.

**D-036 Charged water.** L148: the charged patch is a 4-connected search over liquid-water cells from the contact, nearest first, bounded by 12 cells and 6 m. Ice, dry cells and intact insulation break it; PROP-047 insulation conducts once flooded to Water 3. A body takes the declared damage on its first contact during the 0.6 s charge, and only while grounded with feet within the 0.35 m step height, so a jump avoids it. Local text may shorten the charge, never lengthen it.

**D-037 Conductors and grounding.** L149–L150: the glow before release is 0.25 s (from PROP-001). The 1 m contact area covers the first three branches within 6 m of the contact; a strike within 0.25 m touches a conductor. A grounded conductor absorbs a branch from a direct strike or from a wet patch with a cell within 0.5 m of it. Default capacity is 1; at capacity it overloads and is ungrounded for 4 s (PROP-002, BIO-012), then resets.

**D-038 Wind on volumes.** L151, D-023: translation needs strength above 1 or a stated local override with its distance bound (BIO-011: 2 m). All gusts together move a volume at most 3 m/s. Strength 2 or more removes the columns within 2 m of the leading face, once per gust per volume. Shadow concealment is not wind-movable by default. Wind moves volumes only, never cell units.

**D-039 Extinguish and ignition.** L152: water on a burning cell consumes 1 water and 1 heat (if present), ends the burn, and blocks re-ignition for 2 s. L153: ignition consumes the 2 heat; damage is the growth's declared dps (falling back to the igniting heat's), one hit per second per body, and the growth is consumed after 2 s. A combustible solid ignites once (one fuel layer, BIO-013). Heat never ignites a solid whose flags lack Combustible or Growth (L163 painted stone).

**D-040 Damp sand.** L154: each water unit dampens one sand or dust unit for 3 s and is bound up; dust production = sand + dust − damp. The response "Dry it with bounded heat" is one heat unit drying one damp unit once no liquid water remains, with no steam (`ReactionRules.DryHeatPerDampUnit = 1`).

**D-041 Sound, light, venom, gravity and dispel.** L156: hearing transmission is 0.5 per ordinary solid and 0.75 through absorbent ones (PROP-033); sonic damage passes only on a clear path and reports the nearest destructible solid crossed; volumes never affect audio (L167). L157: a prism reflects once along its fixed face normal keeping 70%; an already reflected ray or a back-face hit is blocked; reflective arena solids reflect along `Box.Forward`. L158: light shafts and BrightLight volumes remove one extra tick of shadow-concealment lifetime per tick. L159: soluble venom dilutes to 50% once any of its cells holds liquid water and never spreads into connected water; soluble venom clouds over water dilute the same way. L160: each field bends a physical projectile once on entry by at most its stated angle, at most 20° in total; magical projectiles and beams are not bent; BIO-023 coils are stricter at 10°. L161: a dispel consumes the oldest removable layer touching its area, a ground field layer or a volume (ties: ground layer first, then lowest id); natural units and solids are never removed.

**D-042 Cell caps, lifetimes and regions.** L163: deposits in one cell merge under the 4-unit cap and share the latest expiry; clipped units are recorded in the unit ledger. Lifetime 0 is instant residue (it reacts that step, then decays). Player material and volumes last at most 8 s (L128). L136: the 128-region cap applies to the representation only. Regions are 8-connected components; above 128 the smallest (ties: lowest index) merges into its nearest region by bounding-box Chebyshev gap. No cell state is ever dropped.

**D-043 Sight blocking.** L167: path length is the union of the segment's intervals inside sight-blocking volumes (overlaps count once); blocking starts at 2 m with a 1e-4 m tolerance. Steam, ash, mist, dust, smoke and shadow block sight by default; illumination, venom cloud and bright light do not. Steam never wets, damages, intercepts projectiles or mutes audio.

**D-044 Order inside a cell.** L165: within the consumption phase the order is extinguish, steam, melt, freeze, ignite, dampen, dry. Water 2 + Heat 1 + Frost 2 arriving in one tick give one steam unit, then one ice tile, whatever the queue order. Queued requests apply in canonical order (server event id, owner, content), never call order.

**D-045 Contact cadence and cell height.** Like L173, a per-second hazard hits each body at most once per second for one second's worth. Cells are 2D with one surface height (the layout patch height, or the first deposit's height while the cell is active), so stacked surfaces share a cell.

**D-046 BIO-001 rain.** Gutter beds are the natural water patches carrying a `RefillRule`; if none does, every natural non-ice water patch is one. Pulses at combat time 8 s, 16 s, … add 1 unit per cell (cap 4) at the start of the 0.5 s visible pulse.

## Stage 1 — Casting (`src/Confluence.Casting`, `docs/notes/casting.md`)

**D-047 Cast weight classes.** L92 gives no quick/heavy threshold: an intrinsic windup of 0.35 s or less is quick (0.20 s recovery, 85% move speed), anything longer heavy (0.35 s, 70%). Tags summon/field are major (0.45 s); tags root/silence/stun/slow/pull are control (0.35 s). A record can only lengthen recovery (`CastingRules.QuickCastMaxWindupSec`).

**D-048 Movement and sprint while casting.** L92: the move factor applies during windup and channel only; preparation and recovery are full speed because grammars keep movement and aim live (L474). L80: `CastMachine.SuppressesSprint` is true for non-quick or channeled casts from preparation through channel; the Sim ends or refuses sprint, and a cast is never refused because the player is sprinting.

**D-049 Cancels and the re-cast lock.** L90, L474: Guard, Dodge and Melee presses cancel; holding Guard blocks opening a preparation. During windup they are a voluntary cancel after commitment: no refund and no recovery. Every cancel before commitment (selection change, silence, ward, low mana and grammar cancel included) applies the 0.15 s (9 tick) re-cast lock.

**D-050 Refunds.** L90, L124: each cast has one shared 25% refund cap (`RefundLedger` keeps the last 8 casts), and each refund effect key fires at most once per cast. The interrupt refund is 25% of the mana actually paid after reductions; its tag is `interrupt_refund` (no base record carries it yet).

**D-051 Silence, hard control and the ward.** L116: silence and hard control cancel a preparation for free and interrupt a committed windup or channel. The spawn-alcove ward (L46) only refuses or cancels preparation.

**D-052 Recast.** L94: refused (`Busy`) while any cast is in preparation, windup or channel, and while silenced, hard-controlled or warded. Casting the same slot again replaces its pending recast. With no stated window the recast stays open until the Sim calls `EndRecastWindow`. Added recovery starts a recovery if idle or extends the current one. Recasts reuse the original `MasteryResult`.

**D-053 Anticipatory cue.** L96: hard control means tags root/silence/stun, teleport means tag `teleport`, and ">70 direct damage" uses the largest number in the record's damage expression. A commit before prepStart + 0.25 s − windup is held inside preparation (still free to cancel), so release is never less than 0.25 s after the cue starts and nothing is delayed after commitment. A windup reward never shortens the cue.

**D-054 Signatures.** L472: activation commits on the press tick with `MissReason.NotApplicable` and the listed windup; no grammar is involved.

**D-055 Mastery caps.** L478–L480: mana-efficiency rewards plus mastery-linked equipment efficiency on one cast clamp at 20%; damage, projectile speed and windup each clamp at 15%; paid cost never drops below 70% (L124). Windup reductions round down and always leave at least 1 tick of a nonzero windup.

**D-056 WIZ-002 pressure release.** A release before 0.20 s queues a normal cast that commits at tick 12 (WIZ-001's roster rule), free to cancel while queued. The crest window is the closed interval [0.40 s, 0.50 s] of hold time (ticks 24–30, crest tick 27). Still holding at tick 36 (0.60 s) auto-vents a normal cast; a release seen on tick 36 counts as a late release. The gauge rises and falls linearly. The reward is +12% direct damage for damaging spells, otherwise 12% less mana.

**D-057 WIZ-010 pressure metering tuning.** The record states no rates. Pressure starts at 30 on the press, rises 60/s while primary is held and falls 50/s while venting (Modifier A), stored as an integer ×60. Pure holding enters 45–55 at 0.25 s and leaves at 0.42 s, so mastery needs at least one well-timed vent of 0.1 s or more. Mastery is 15 consecutive in-band ticks before release, for 15% less mana. A release before 0.30 s queues a normal cast at tick 18. Leaving the 20–80 band vents for 0.30 s and then auto-commits a normal cast (free to cancel during the vent). Holding to 0.90 s (tick 54) auto-vents (`HeldPastWindow`). Vent toggles are limited to one per 6 ticks; throttled input inside the qualifying run reports `TooFastToggling`.

**D-058 Guided normal route.** L470: a tap opens a fixed preparation equal to the record's stated normal preparation, always `MissReason.Guided` with no reward. WIZ-005, -008, -009 and -017 state no fixed normal preparation and have no guided route.

**D-059 Voice, rhythm, strokes and aim.** L365: a syllable below the calibrated confidence threshold keeps its place as an unrecognized token; the phrase cannot commit and the miss names that beat. L367: the rhythm route uses the same `BeatScorer` tolerances. L369, L490: strokes are resampled evenly along the path, centered, rotated only if the rune allows it, and scaled by bounding box; direction-key tracing compares the 8-way segment structure. WIZ-001's "2-degree cone for the final 0.25 s" means every aim sample in that window lies within 2° of the release aim. Tokens pressed in the same tick are read in alphabet order; a single-selector chord presses both inputs on one tick (spread 0).

**D-060 Cast event ids.** (player, sequence), with the sequence incremented for every opened attempt, cancelled ones included, so server and client ids agree.

## Stage 1 — Arena (`src/Confluence.Arena`, `docs/notes/arena.md`)

**D-061 Functional symmetry.** L308 "functional symmetry is mandatory": a half turn about the center. An element at (x, z) with yaw a has its image at (−x, −z) with yaw a + 180°; side 0 spawns on −Z, so both players get the same left and right. L321 "mirrored distances": navigation is exactly symmetric on symmetric layouts (mirror-equivariant tie-breaks; clearance takes the smaller of each mirrored pair). The validator fails any layout whose graph is not its own half-turn image; `ArenaRules.ParityDistanceTolerance` is 0.05 m, and the fairness probe compares per-node mirrored spawn distances within 0.01 m.

**D-062 Contraction validity.** L48, L676: every 2.5 s from 55 s to 85 s, every accessible cell at least 2 m inside the moving contour keeps a capsule route to the final floor through cells at least 0.4 m inside the contour. An interval in which a cell is first cut while still outside the 2 m band is re-sampled at 0.3125 s (`ArenaRules.ContractionRefineSteps` = 8).

**D-063 Central reach and central cover.** L310 "mobile melee build … 2.0 to 3.5 seconds without spending its signature" is measured at walk speed: generation ignores builds (L325) and sprint disallows melee strikes (L80). Useful central cover is a main-floor capsule node within 5.5 m of the center (final radius + 1.5 m) and within 1 m of a cover solid that alone blocks the line from a crouched body (0.7 m) to the opponent's spawn eye.

**D-064 Path band, lanes, area and cover ratio.** L310: the spawn-path band scales linearly with diameter, minimum 16 → 22 m and maximum 32.5 → 34 m from 24 m to 48 m arenas (`ArenaRules.SpawnPathBand`). Lanes are measured in the 1.2–1.6 m chest-to-eye band on the main floor, 24 directions every 0.5 m; low 1 m cover and props never interrupt a lane. L306: usable area targets π r² of the tier diameter within 10%. Cover is sight-blocking solid at least 1.0 m high (crouch eye), 18–30% of usable floor.

**D-065 Route redundancy.** L312, L322: two approaches are disjoint when no 3 m wall or field (a 1.5 m disc plus capsule) can touch both, except inside the 3 m spawn-alcove radius and on the final floor. Representative 3 m walls are tested every 2 m along each approach.

**D-066 Module composition.** L660: 2–4 elevation and 3–6 cover modules, placed in mirrored pairs (even counts). L317: a 48 m arena first places one landmark pair (a topology, elevation or approach module with a footprint of at least 8 × 4 m), which takes that arena's topology budget; without it nine topology modules and the 10 m elevation decks never fit.

**D-067 Retries, repair and fallback.** L323, L455: up to 8 seeded attempts (`ArenaSchedule.AttemptSeed`, Arena stream). Fallback k for a size and biome uses seed `SeedHash(salt, diameter, biome, k)`, built conservatively; the first k that validates is the fallback, computed on first use and cached. All 96 size × biome fallbacks exist and pass the fairness probe; a fallback release reports 8 attempts and 8 rejected reports. Contraction repair keeps a filler change only if it rescues the stranded cell and opens no lane over 28 m; otherwise the nearest lane-safe rock is removed and the search repeats (up to 12 times).

**D-068 Props.** L662 and each prop's placement text: 3–8 definitions with two mirrored instances each, at most 48 instances. A prop is never within its placement radius + 0.75 m of the final circle or within reach of a spawn alcove. Props are navigation obstacles and never supports, so routes are validated with props in place. If the availability filter offers fewer than 3 definitions, the minimum becomes the available count.

**D-069 Biome geometry.** L335: biome rules are geometry in Arena; sources and objects are placed in mirrored pairs with the rule string in `MaterialPatch.RefillRule`. Where a biome gives no durability, the matching catalogue module or prop supplies it: BIO-005 from MOD-021 (100), BIO-012 from MOD-043/PROP-002 (80), BIO-016 from PROP-038 (30), BIO-017 from PROP-018 (30), BIO-020 from MOD-045 (90), BIO-022 from PROP-007 (40). BIO-011 gusts run along ±X, across the spawn axis, so they push toward neither spawn (a uniform direction cannot itself be half-turn symmetric).

**D-070 Cosmetic variation.** L319: drawn from a separate sub-stream of the layout seed; never part of collision or `ArenaLayoutHash`. Mirrored modules draw art independently because visual symmetry is optional (L308).

**D-071 Arena build settings.** The Arena library compiles with `<Optimize>true</Optimize>` in every configuration and its test host uses server GC, because generation runs hundreds of navigation builds per arena. The 960- and 2000-arena batches carry `[Trait("Category","Slow")]`.

## Stage 1 — Economy (`src/Confluence.Economy`, `docs/notes/economy.md`)

**D-072 Shop offers, rerolls and folding.** L206: D-020 as written, where "visible" includes folded placeholders and the definition a reroll replaces. L206, L208: a reroll with no possible alternative leaves the card as it is and keeps its reroll; an outside-budget placeholder with an empty affordable pool shows Save Crowns and keeps its reroll. After each purchase every remaining offer priced above the new balance folds into a placeholder, whose unused reroll draws from the affordable pool at reroll time. Selling never refills cards or restores rerolls (L208, L587).

**D-073 Economy request ids.** L429: ids must be positive. Every processed request, failures included, is stored for the whole match; a repeat with the same operation returns the stored result without reapplying it, and the same id with a different operation returns `RequestIdConflict`.

**D-074 Sell value and used consumables.** L212: floor(paid price × 0.5). A used consumable stays as an inert shell that sells for 0 and is then removed; it supplies no tags and does not count for `owned_item` or `consumable_charges_at_most`.

**D-075 Active items.** L575: an active item placed in a slot that can activate becomes the enabled active when none is enabled; the player can change or clear the choice in the shop. The Sidearm is never the enabled active (L577). L585: a disabled active supplies no effect tags (including `active_equipment`), only its category identity tag (wand/staff/weapon) and its category.

**D-076 Equipment predicate leaves.** L625: `issued_slot` is true when the slot holds no purchased item (for Trinkets and Consumable, when it is empty); `slot_tier` is never met by issued gear. L627, L635: `equipped_category` counts distinct equipped definitions, and with `distinct_unique_groups` counts distinct nonempty Unique groups. L615, L585: `equipped_tag` counts distinct equipped definitions (not the reserve) that supply a live tag.

**D-077 Acquisition-only leaves.** L247, L602: `wizard`, `round_at_least` (compared per D-029) and `feat` are evaluated once at acquisition and stored in an `AcquisitionRecord`; the stored truth value is reused afterwards, including under `not`. All other leaves are ongoing. Feat leaves count completed non-training duels (L280, L633).

**D-078 Two-profile rule.** L243, L543, L637: transformations are judged against the base-kit profile; shared augments against the profile with enabled transformations and live equipment structural changes. Shared augment effects never add tags, and an augment never counts itself as its own parent.

**D-079 Dormancy order.** L641: resolve transformations first, rebuild the profile from the active ones, then resolve shared augments, each group walked topologically over augment-to-augment references. A dormant parent makes its dependents dormant. A cycle leaves its members dormant and is flagged as invalid content (L643).

**D-080 Draft guarantees.** L227: "universal" means a shared augment with eligibility `{always:true}` and no `eligible_wizards`; "broadly conditional" means a shared augment with no wizard list whose predicate reads only current equipment or equipped-spell profile leaves (no wizard, spell, augment-lineage, feat or round leaf). L645: with all six slots full a new card needs an explicit target slot, and `confirmDormancy` when the preview lists augments that would go dormant. ## Stage 1 — Match (`src/Confluence.Match`, `docs/notes/match.md`)

**D-085 Reveal and early ready.** L44, L329: the reveal has no stated length; it is 0 s (`MatchRules.RevealSec`) and its information stays visible through the shop, which opens on the start tick. L45: early ready requires every active contender who opened a shop this round, bye players included. A player past the 90 s reconnect window (L55) counts as ready; one still inside it does not.

**D-086 Missing duel outcome.** L47, L427: if a duel reports no outcome by the 90 s combat cap plus 1 s grace (`MatchRules.OutcomeGraceSec`), the pass is voided for everyone. A void rerun reuses the same seats with a new arena seed, no shop, and no replay counted. Voided duels never reach the economy or feat ledger.

**D-087 Winner bonus.** L193, L61: +100 goes only to winners of a previous-round fight that was neither a draw replay nor voided; a win in a void rerun earns it. Draws, regular byes, bracket byes and walkovers, and replay wins earn nothing. Replay passes have no shop and no income.

**D-088 Regular-round draws and elimination.** L36: a regular-round draw is final; both players lose `ResolveLoss(round)` and nothing replays. Resolve is clamped at 0. Every player at 0 leaves together once the round's last duel resolves and takes the block of positions just below the survivors, each at the block's mean (L40).

**D-089 Bracket placements.** L38, L40: losers of one bracket round share a placement block (quarterfinal losers 5–8). Both players of a twice-drawn bracket match join that round's block, and their next opponent advances by walkover. A bracket round with only walkovers is skipped (no shop, no arena). A twice-drawn final has no champion (`MatchResult.Champion = NoPlayer`, both at 1.5).

**D-090 Bracket seeding and shops.** L38: order by Resolve, then combat wins, then fewer regular byes, then the recorded lobby seed (Bracket stream, round 0, sub = player), then player id. The bracket size is the next power of two; standard slot order gives empty slots to the highest seeds, and seeds 1 and 2 can meet only in the final. Tier 4 stays unlocked throughout the bracket (`ShopOpening.HighestUnlockedTier = 4`); there are no drafts in the bracket or in replays (L225).

**D-091 Pairing cost.** L59: lexicographic over sums across all pairs: (1) immediate rematches, (2) pairs repeating either player's previous two opponents (an immediate rematch counts here too), (3) total absolute Resolve difference, (4) total absolute combat-win difference. All (n−1)!! matchings are enumerated; exact ties are a uniform pick among optimal matchings with the round seed (Pairing stream, round r, sub 0). Opponent history counts draw replays and skips byes.

**D-092 Sides and byes.** L59: per pair, the seating with fewer third-consecutive-side violations wins, then fewer repeated sides, then a seeded coin (Pairing stream, sub 2 + attempt). L61: "waited longest since a bye" is the earliest last-bye round (players who never had one count as round 0 and tie); the final tie is a seeded pick (Pairing stream, sub 1). Bracket byes do not count toward `RegularByes`.

**D-093 Duel mode scoring.** L65: a Duel round that draws three times (original plus two replays) scores a half win each and the round advances. Round 8 is the decider at 3.5–3.5; a drawn decider replays once (`GlobalRules` DuelDeciderAttempts = 2) and a second draw records a match draw with both at position 1.5. Decider draws never score half wins. A replay win counts as a full win without the bonus. A private rematch is options metadata only; `DuelMatch.RematchSeed(prev) = SeedHash.Combine(prev, hash("confluence.duel.rematch"))`. The Duel fingerprint only separates ranked from unranked.

**D-094 Conclave presets and custom settings.** L71: "rule presets" is the `ConclavePreset` enum (Ranked/Unranked/Custom); "seed rotation" is an optional host list of arena seeds, where round r uses entry (r−1) mod count and replays use `SeedHash.Combine(hostSeed, attempt)`; an empty list means per-round seeds from the match seed (L34). L66–L67: Ranked and Unranked must use the standard rules; only Ranked with standard rules counts for rating, and Custom lobbies never do. The fingerprint is a SeedHash of canonical text listing every rule-relevant setting (allowed content as a sorted, distinct set), shown as 16 hex digits. Bounds with no spec value (`MatchRules`): custom shop timer 5–300 s, starting Crowns 0–100000 (replacing only the first-shop 600), spectator delay 15–600 s (L391 gives only the minimum).

**D-095 Arena per pass.** L34, L306, D-028: one balanced diameter sequence per match covering 15 scheduled rounds for Conclave (12 + 3 bracket) and 8 for Duel (7 + decider). Each pass sends one arena request that every pair shares; replays keep the round's diameter with a new seed.

**D-096 Loadout visibility and feat counting.** L44, L46: the reveal shows the opponent's loadout as finalized at the previous round's alcove; from the alcove on, and through replays and reruns, the opponent's current-round final loadout is visible. L280: feats count once per completed duel per player; voided duels never count; a drawn duel that is replayed still counts as completed.

**D-097 Outcome validation.** L53: a time outcome is checked against `DuelJudgement.WinnerAtTime` with `GlobalRules.Round.DrawThresholdFraction`. Death and Surrender outcomes need a winner; SimultaneousLethal must be a draw.

## Stage 1 — Sim core (`src/Confluence.Sim`, `docs/notes/sim-core.md`)

**D-098 Motor tolerances.** L80, L175, L312 (`SimRules.Motor`): 30.5° walkable tolerance on the 30° cap; ground snap equals the 0.35 m step height; sprint needs forward input above 0.1; ice ground-acceleration factor 0.2, which traction interpolates back to 1; kill plane 6 m below the lowest walkable top; terminal fall speed 30 m/s; 0.15 m collision substeps.

**D-099 Falls, steps and rule damage.** L175: fall height runs from the peak support height to the landing support, so rolling off a ledge does not shave the drop. L312: step-up checks the touched surface height, so a 0.5 m block cannot pass as a step. Fall damage is physical ("10 physical damage per excess meter"): resistance, passives and shields apply, guard does not. The recall penalty (L175) and the 5-point edge impact (L51) are rule damage: they bypass all mitigation and trigger nothing.

**D-100 Knockback and hard control.** L116, L173: hostile knockback is the hard-control status Displaced, lasting at most 0.75 s; control immunity blocks it while the damage still lands; it interrupts casts and cannot be dispelled. Default knockback speed is 12 m/s (`SimRules.Displacement.KnockbackSpeed`; the 4 m cap takes 1/3 s). Hard control shares one continuous 0.75 s window across overlapping sources; the 2 s immunity starts when the last hard control ends, and refused control is not queued.

**D-101 Edge impacts, dashes and teleports.** L51, L124: the edge impact applies only to hostile knockback; self dashes stop at the boundary without damage. Teleports clamp to 10 m, are pulled inside the boundary by the capsule radius, and fail if the destination is inside collision.

**D-102 Melee strikes and profiles.** L100–L102: the strike volume is live for 3 ticks after the windup with 3 samples per tick, from 0.35 m below the eye along the committed yaw and pitch (no tracking). Thrusts (butt strike, spear) go straight; light blades sweep ±35° and heavy weapons ±45°. Reach runs from the attacker's center line to the target capsule surface. One opponent hit per attack; each solid is contacted once per attack and takes the profile damage as durability; a stun cancels a strike still in windup. L100: weapons tagged heavy, spear or light_blade use that profile, other weapons light blade; wands and staffs use focus; an empty slot is the issued plain focus (L571).

**D-103 Guard and focus swap.** L104: guard needs a fresh press during combat and releases on button release, the 0.8 s hold limit, stun, death or recall. The 0.25 s "clearly punishable" release window blocks dodge, melee and casting. The perfect window is 7 ticks (0.12 s rounded). The arc test uses the request's source position. L106: a dedicated `SwapFocus` input toggles Main Focus and Sidearm in 21 ticks, refused during melee, cast busy or recovery, or guard; spell-slot selection applies on the same tick.

**D-104 Healing and shields.** L114: "per second" is a rolling 60-tick window. Lifesteal counts toward the 35/s window, its own 20/s window, and the 120 duel budget; healing beyond missing health consumes no budget. A compatible shield is one with the same source id and reserve flag, and a larger grant tops it up instead of stacking. The 100 cap trims grants at gain time; timed shields last min(duration, 8 s).

**D-105 Mitigation.** L112: resistance is clamped to [−15%, 35%] and then multiplied with each passive reduction, with total reduction capped at 45% (multiplier floor 0.55). Guard comes first and is exempt (L106). L110: precision is clamped to [1, 1.25] and applies only to precision-tagged damage.

**D-106 Statuses, slows and dispel.** L118: DoT pulses every 0.5 s (`SimRules.Status.DotIntervalSec`) for intensity × 0.5, first pulse 0.5 s after application; a same-definition refresh keeps the later expiry and the strongest intensity. L175, L116: surface slows (sticky growth) join the strongest-slow rule and its 30% cap; wet stone has no movement effect. L118: dispel removes the oldest status that is both harmful and removable, or the explicitly selected one; Displaced and Invisibility are not dispellable, and control immunity is not a status.

**D-107 Proc budget and chains.** L126: a trigger needs 30 ticks since that effect's last trigger and an unused (origin hit event, target) pair, keyed per (owner, effect id). Chains pick the nearest unvisited candidate within 6 m of the previous point (ties: lower id), at most 3 jumps.

**D-108 Boundary, timer and surrender.** L51: the escalation tier comes from ticks accrued outside, and a reset needs 60 consecutive ticks inside; FEAT-024 (L278) counts a reset after boundary damage only once contraction has started. L53: a timer draw when the health-fraction difference is below 0.005, each player against their own maximum, shields excluded. Both players surrendering in one step is a draw; a surrender resolves at the end of the next step.

**D-109 Alcove and recall.** L46: feet are confined to the alcove footprint inset by the capsule radius (`SimRules.Duel.AlcoveFallbackHalfSize` = 2 m when the layout gives none); damage, statuses, owned entities, mana commits, guard, melee and swap are refused; jump and dodge are allowed and stamina spent there is not restored at combat start. Players are snapped to the ground at spawn and on recall. L175: recall returns the player to the nearest standable point on a non-dynamic walkable solid near the fall position, at the last grounded height and inside the legal boundary (spawn as fallback), holds them for 30 ticks, and keeps the dodge cooldown.

**D-110 Walls formed under a player.** L171: if the player's feet are inside the new solid's footprint, the lift is at most 0.5 m, and there is headroom, the player is raised onto it; otherwise `AddTemporarySolid` returns −1 and the caller refunds the placement.

**D-111 Lag compensation and decisive sequence.** L423: only player capsules are rewound, to the input's view tick clamped to the last 9 ticks (`SimRules.LagCompensation.MaxRewindTicks`); solids, fields and projectiles are tested as they are now. L359: the decisive sequence keeps the last 5 s (`SimRules.Duel.DecisiveSequenceSec`) of events about the player: damage with its full resolution and reaction tag, statuses applied or blocked, guard outcomes, knockback, edge impacts, falls, and the end event.

**D-112 Feat counting.** L253–L278: FEAT-005 counts self-propelled horizontal distance in combat (walk, sprint, jump, dodge, dash; not knockback). FEAT-008 counts any original-generation hit within 1 s of a dodge start. FEAT-022 counts a spell hit followed by a melee hit within 1 s, each spell hit used once. FEAT-023 counts dispelling one's own hostile statuses. FEAT-019 counts a stun, silence or displacement that interrupts a committed cast. FEAT-012 uses per-channel post-mitigation damage.

## Stage 1 — Net foundation (`src/Confluence.Net`, `docs/notes/net.md`)

**D-113 Version handshake.** L427: the ruleset fingerprint is SHA-256 over `CONFLUENCE-RULESET\0` + UTF-8 `NetRules.RulesVersion` + `\0` + the catalogue bytes with a leading BOM and every CR byte removed. Any protocol, ruleset or required-build mismatch is rejected with a `ConnectionRejection` carrying the server's protocol, rules version and fingerprint, which drives the unsupported-version state. The handshake magic and protocol version form a frozen preamble checked before the full decode. Bump `NetRules.RulesVersion` on any rule-code change.

**D-114 Reconnect window.** L55: the 90 s window is inclusive and measured from when the server sees the disconnect, on an injectable `INetClock`. A resume must still match the protocol and ruleset. A newer connection takes over a still-live session; a kick retires the session unless `allowResume`. Expired tokens stay mapped, so a late reconnect reports `ReconnectExpired` rather than `UnknownSession`. Capacity counts connected plus resumable sessions.

**D-115 Snapshot rate selection.** L421, D-005: congestion means 1 s windowed packet loss of at least 5%, a reliable backlog of at least 32, or RTT at least 80 ms above the 10 s RTT floor. The rate drops to 20 Hz after 500 ms of congestion and returns to 30 Hz after 3 s clear; sends are spread evenly over 60 Hz ticks.

**D-116 Transport request dedupe and rate limits.** L429: request ids are client-assigned and increase per player. The server keeps the last 64 framed responses; a duplicate gets the original bytes back and older ids answer `Stale`. RateLimited answers are not recorded, so the same id may run later; handler exceptions are recorded as `ServerError` and never rerun. Tuning (no spec values): rerolls burst 3 then 1 per 250 ms, transactions 5 then 1 per 200 ms, chat 4 then 1 per s, clock pings 8 then 1 per 50 ms. Economy's match-long request store (D-073) sits behind this layer.

**D-117 Rejecting impossible values.** L429: `NetReader` rejects NaN and infinite floats, booleans other than 0/1, out-of-range enums and counts, over-long varints, invalid UTF-8 and trailing bytes. Positions beyond ±512 m are rejected as an anti-forgery bound (arenas are at most 48 m, L306), not a gameplay rule. A connection reaching 64 violations is closed.

**D-118 Spectator delay buffer.** L391: `SpectatorDelayBuffer` raises any shorter requested delay to `GlobalRules.Match.SpectatorDelayMinSec` (15 s); `ReleaseAll` is for after the match only.

**D-119 Interpolation and input buffering.** ARCHITECTURE networking: remote entities interpolate 100 ms behind (`NetRules.InterpolationDelayMs`). Each input packet carries 4 redundant earlier inputs. The server repeats the last input for up to 6 starved ticks and then uses a neutral input, buffers at most 12 ticks ahead, and drops a late input whose tick was already written off.

**D-120 Transport time, tokens and impairment.** Transport timers, the reconnect window, rate limits and clock sync use `INetClock` (Stopwatch-based), not sim ticks: they manage connections and decide no rule outcome. Reconnect tokens come from `RandomNumberGenerator` (`CryptoTokenSource`) because they are credentials; tests use `SeededTokenSource` on `Rng`. LiteNetLib's release build ignores its loss and latency simulation, so impairment tests use `UdpLinkSimulator`, a seeded UDP relay.

**D-207 Damage-scope and cover terms.** "Direct player damage decreases 2%" (AUG-059, 125) = the owner's direct spell hits on players (splash, fields and weapons unchanged); "airborne-target damage" (AUG-030) = the owner's spell hits on an airborne target. "Enemy-created cover" (AUG-059) = any destructible solid the opponent created; "cover object" (AUG-067) = any destructible solid (props, cover, spell walls); "dry destructible" (AUG-125) = a destructible prop whose cell holds no liquid water; "heat effect" = school Heat, a heat tag, or the thermal channel. Because `SolidEvent` carries no source, AUG-059/067 record "my spell's direct impact hit solid X" inside `AdjustSolidDamage`, whose returned amount stays a pure function of its inputs.

**D-208 Mastery-linked bonuses.** L480: the Casting mastery family (records tagged `mastery`) report direct-damage and projectile-speed bonuses (AUG-001, 006, 007, 009, 013, 018, 020) through `EffectHook.LinkedDirectDamage/LinkedProjectileSpeed`; they are summed per cast and clamped once with the cast's own reward at 15%. Mastered-only cost reductions are efficiency and clamp with a mana reward at 20% (`MasteryClamp.RewardedCastEfficiency`). Speed and damage edits that are not mastery-linked (AUG-025/026/103) stay outside that clamp.

**D-209 One reward per cast, cross-category reading.** L124 "never both" limits the grammar reward itself; mastery-linked records of a different statistical category (AUG-005 windup, AUG-014 mana, AUG-020 damage on a mana-rewarded cast) still apply under the full combat caps (L480 "Different statistical categories still obey the full combat caps"). The strict reading would make AUG-005 inert for all ten wizards it lists, none of which has a windup reward.

**D-210 Gait requests.** Records request signed walk/sprint changes through `AdjustGait`; the host sums them. Bonuses join the stat block's gait bonus under the +20% cap; penalties apply after the cap, so a drawback is never absorbed by it. Only the change is applied on top of the command's multipliers, so other edits to the command survive.

**D-211 augments-a record readings.** AUG-031 "release at least 1 m above enemy feet" = the caster's feet at least 1 m above the enemy's feet at release (from the eye every level release would qualify). AUG-062 "within 4 m" = horizontal distance from the owner's feet to the prop's base centre. AUG-082: a second weapon hit inside the 1 s window cancels the setup; the projectile must be released inside the 1 s; a projectile hitting on its release tick is boosted when the record's 0.5 s proc interval is open, with the activation recorded once at the dispatch point. AUG-088 "within 2 m of solid cover" = a vertical solid face within 2 m (16 waist-height probe rays, `AugmentsAKit.NearVerticalSolid`, also used by AUG-105). AUG-105's lateral motion is a 0.1 s self displacement after takeoff (motor collision, legal boundary), after which the jump's horizontal velocity is restored, so exactly the stated distance is added and no height; it emits a wall-exit marker. AUG-117 spreads its 2 (4) stamina over the first 30 ticks of a sprint begun with the cooldown ready; the 5 s cooldown runs from that sprint.

**D-212 Draft requirements in the duel.** Records whose draft requirement is equipment, a feat or another augment do not re-check it in the duel; Economy eligibility and dormancy (L602–L646) decide when they are active.

**D-213 Record markers.** AUG-043's trail (launch point to end, launch direction) and AUG-105's exit (takeoff to the shove's end, visible until about the landing) are public `MarkerEvent`s with From/To/Direction/DurationTicks: authoritative events both clients receive, with no rule effect or collision (delivery over the wire: D-225).

**D-214 AUG-109 Wet Route stays unimplemented.** L175 and the Water Pool record ("no automatic slow") give shallow water no movement penalty, so the record has nothing to reduce; reducing every slow on a wet surface (enemy spell slows included) is not what the record states. ## Stage 3 — game protocol (`src/Confluence.Net/Game`, `Confluence.Server`, `Confluence.HeadlessClient`, `docs/notes/net.md`)

**D-215 Rewind and interpolation.** L423: the 150 ms rewind covers the whole stepTick − viewTick distance, interpolation included; shots are fully favoured up to about 60–70 ms RTT and clamped beyond. The interpolation delay adapts between 50 and 250 ms ("about 100 ms" is the typical value, not a cap), with one snapshot interval of headroom; starved frames report the held tick. A rewind never crosses a teleport, recall or alcove placement (`HitVolumeHistory` discontinuities).

**D-216 Information release.** L49, L391: opponent health is never sent during a duel; damage amounts go only to attacker and target; results show both health fractions afterwards. A result goes to its two duelists at once and to every other seat when it is 15 s old, when no duel of the pass is live, or at match end (one `MayKnow` rule on the normal, deferred and reconnect paths). Standings change only at pass resolution and reach a live duelist after its duel or the delay. On reconnect the server replays the seat's released results, own reports and last released standings; a seat resuming after the match gets settings, final standings, every result, its reports and `MatchEnd`. The client keeps one result and report per duel id and raises `MatchEnded` once.

**D-217 Hidden opponents.** L120: a hidden opponent's live pose is replicated exactly when `DuelWorld.IsVisibleTo` is true (the 4 m silhouette) and otherwise culled on the server with no early-reveal margin; the client never interpolates between a frozen hidden pose and a live one. `DuelEventFilter.Conceal`: for a hidden opponent, cast and movement events always lose position and direction; every event it acts in loses its direction; events it acts in, takes damage in or is targeted by lose any position within 3 m of its live position; reaction cues its own effects cause within 3 m are dropped; neutral terrain reactions and far positions stay. Owner-attached entities (Movement, Buff, Other) carry the origin and are drawn on the owner's replicated pose; a hidden owner's attached entities are left out of the frame. Hidden-player footsteps (L120 "does not suppress footsteps") are still open.

**D-218 Network tuning.** Incremental cell capture refreshes the active cells plus the cells reported last time (exact because every non-empty Reactions cell is active), with a full scan on the first capture and every 30 captures. D-115's 5% loss threshold is snapshot loss over a sliding 4 s window. Input queue target 1 tick, surplus cut above 4 ticks after 0.5 s, rate limit burst 32 then 1 per 8 ms, kick after 2000 rate-limited or faulting messages. Grammar events may be back-dated 1 tick (taps, traces, widgets, stroke ends) or 9 ticks, the rewind bound (syllables, stroke samples). View claims: declared interpolation clamped to 3–15 ticks, slewed 1 tick per 20 arrival ticks per session, capped at one-way + min(jitter, 3) + snapshot interval + 2; the jitter widening of the tolerance is capped at 3 ticks.

**D-219 Seeds and arena download.** Standard matches use a cryptographic random match seed; `--seed` needs `--lab` or `--allow-fixed-seed`. A client that cannot regenerate an arena exactly downloads the server's layout; only a failed download is the unsupported-version state (L427). The arena seed is public (arena id, layout seed field covered by the layout hash), so withholding the recipe seed would not close the leak; HMAC-derived hidden streams with an independent arena root are an open blocker before any public server.

**D-220 Tap edges.** A button pressed and released inside one command is a press edge for every action (melee, guard, jump, dodge, swap) in `DuelWorld.ApplyInput`, as it already was for casting; a tap of a button held before or now is no new press. `MotorPredictor.PressedEdges` mirrors it.

**D-221 Transport and pacing.** Production transports (server, headless client, `GameTransport.Defaults`) run LiteNetLib's threads (`ManualMode = false`) to mitigate #616 until a fixed release is pinned (`--manual-transport` opts back in); virtual-clock tests keep manual mode. The accelerated pace is at most ×16 (`NetRules.MaxTickRate` 1000, the rate Welcome can decode); the server refuses faster. Reliable-lane latency is measured with real-time pacing (`GameRig.PaceRealTime`) because LiteNetLib times resends by wall clock.

**D-222 Session lifecycle.** Wizard choices freeze once the `MatchHost` exists (the arena warm-up): a join with another wizard is refused with `MatchRunning`, an identical re-join accepted, and a seat expiring during the warm-up is kept. The client holds snapshots, events and reports of a duel whose `DuelStart` has not arrived (up to 512 messages per duel id); an authoritative Ended snapshot ends the client duel. The private entry carries `RecallEndTick` (protocol 3) and the predicted motor holds while tick < RecallEndTick. Metrics flush a record for every live duel at shutdown plus one session summary per human seat.
